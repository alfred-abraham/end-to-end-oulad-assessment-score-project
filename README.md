# OULAD assessment score estimator

A Flask regression demo using the Random Forest selected in
`notebook/Model Training.ipynb`. Contextual inputs are retained;
previous assessment results are optional. The application calculates the history features.

## Major findings

The recorded experiment compared models on the same student-disjoint 60/20/20
train/validation/test partitions. Model selection used validation RMSE; the test
set contained 33,774 assessment records from 4,659 held-out students. The selected
context-only model was XGBoost, and the selected model with history was Random Forest.

### Validation comparison of all five algorithms

Both feature sets were rerun with Linear Regression, K-Nearest Neighbors (KNN),
Decision Tree, Random Forest, and XGBoost. KNN uses 25 neighbors; Decision Tree
uses maximum depth 12 and at least 20 samples per leaf. These restore the earlier
context-only settings. All algorithms use the same student splits and preprocessing;
no hyperparameters were tuned against the rerun's test results.

| Algorithm | Context RMSE | Context MAE | History (28 days) RMSE | History (28 days) MAE |
| --- | ---: | ---: | ---: | ---: |
| Linear Regression | 17.73 | 13.64 | 16.29 | 12.21 |
| K-Nearest Neighbors (KNN) | 17.78 | 13.58 | 15.44 | 11.35 |
| Decision Tree | 17.54 | 13.48 | 15.54 | 11.45 |
| Random Forest | 17.22 | 13.24 | 14.99 | 11.01 |
| XGBoost | 17.05 | 13.13 | 15.03 | 11.09 |

The added algorithms did not change the winners: XGBoost has the lowest
context-only validation RMSE, and Random Forest has the lowest validation RMSE
with history. Simple mean/median and prior-score baselines are also evaluated in
the [executed notebook](notebook/Model%20Training.ipynb).

### Test results for the validation-selected models

Only validation-selected models and the established simple baselines are evaluated
on the test set; test scores do not select the winning algorithm. The selected-model
test metrics and the robustness-check outcome are unchanged after this rerun.

| Model / assumed grade-release delay | Test R² | Test RMSE | Test MAE |
| --- | ---: | ---: | ---: |
| Context-only reference (XGBoost) | 0.160 | 17.13 | 13.08 |
| Context + assessment history (Random Forest, 28 days) | 0.351 | 15.06 | 11.03 |
| Context + assessment history (Random Forest, 56 days) | 0.300 | 15.63 | 11.56 |

RMSE and MAE are measured in assessment score points; lower is better. R² is a
regression measure, not classification accuracy.

- **Assessment history improved the recorded predictions.** With the 28-day
  availability assumption, test RMSE fell by **12.1%** and MAE by **15.7%** relative
  to the context-only reference. This compares two selected model pipelines; it
  does not isolate the effect of adding history to an otherwise identical model.
- **The result depended on when grades were assumed available.** With a 56-day
  delay, RMSE improved by **8.7%** and MAE by **11.7%**. The experiment therefore
  **did not pass its predeclared notable-improvement gate**, which required at
  least 10% reductions in both errors on validation and test under both delays,
  plus positive lower 95% student-bootstrap bounds for the test improvements.
- **Predictions were less reliable when history was unavailable.** In the saved
  28-day model, test MAE was **10.13** points for records with usable history and
  **13.62** without it. About **74.3%** of test records had usable history. These
  groups contain different records, so this is not a controlled comparison.
- **Assessment context and previous grades carried predictive information.**
  Individual permutation importance ranked assessment weight, assessment type,
  and mean prior score highest. Correlated inputs can share importance, and
  these associations do not establish causes of student performance.

These findings support a retrospective demonstration. An average absolute error
of about 11 points still leaves substantial uncertainty for individual estimates.
The holdout had been inspected previously, and actual grade-release timestamps
are unavailable; the results do not establish performance on future courses or
suitability for high-stakes student decisions.

## Run locally

Use Python 3.12 and run these commands from the project folder:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m src.pipeline.train_pipeline
python app.py
```

Open <http://127.0.0.1:5000>. The training step creates
`artifacts/history_model.joblib` (the complete fitted preprocessing + model pipeline)
and `artifacts/model_metadata.json` (schema, assessment schedule, categories, measured
metrics, versions, and model checksum). Artifacts are included when generated by this
project update; retraining is optional if the recorded dependency versions match.
Use only trusted local model files. Restart the app after replacing artifacts, since
the fitted pipeline is cached in memory. Training does not run during web requests.

For a WSGI server instead of Flask's development server:

```powershell
python -m waitress --listen=127.0.0.1:8080 app:application
```

This update prepares a runnable demo; it does not publish the app or provision hosting.
The Elastic Beanstalk entry point is `app:application`.

## Form inputs

Select the module, presentation, and assessment being predicted. The public OULAD
schedule supplies its assessment type, weight, and deadline. Enter gender, region,
highest education, deprivation band, age band, previous course attempts, studied
credits, and disability. Options retain the dataset's original category values.

Optionally add previous assessments from that same student's selected course offering,
with their score and submission day. Days are relative to the course start, not calendar
dates. The assessment selector supplies each previous deadline and ID, which are
necessary for consistent ordering and validation. Changing the course offering clears
previous entries to prevent accidentally mixing courses.

Leaving history empty uses `prior_count=0` and missing summary statistics, exactly the
no-history representation seen during training. The saved pipeline imputes those
statistics using training-fitted values. This is the history model operating without
history, not a switch to a separately trained contextual model.

## History rules and limitations

- Predict one day before the target deadline.
- A source grade is usable only when `max(deadline, submission_day) + 28 < prediction_day`.
- Do not enter the target assessment, duplicate assessments, or another student's results.
- Scores too recent for this rule are excluded and their count is shown in the result.
- Grade-release timestamps are absent from OULAD. The 28-day delay is an assumption,
  not a verified marking guarantee. In a real system, require actual grade-release times.
- Records with unknown deadlines cannot be selected or used as historical inputs.

The model uses the same 150-tree Random Forest recipe, student partitions, imputation,
encoding, and scaling as the history notebook. Training rebuilds student-disjoint
60/20/20 partitions, fits the selected recipe on training + validation, and reports
performance only on held-out students. Earlier available grades belonging to those
students can supply sequential inputs; their targets never fit the model.

The expected primary test results are approximately R² **0.351**, RMSE **15.06**, and
MAE **11.03**. Runtime values come from the generated metadata. These are overall
assessment errors, not individual confidence intervals. Errors differ by subgroup,
and no-history estimates have less information. This is a retrospective student-disjoint
comparison, with a previously inspected holdout, not proof of future-course performance.
